## 1. 背景与问题

密友之间真正有价值的瞬间，往往沉在相册里：没发朋友圈、没进 Story、只有当事人懂的梗。公开社交（Instagram / TikTok）偏向表演与分发；纯聊天工具又缺少「被发现的惊喜」。

**问题陈述：** 如何让小圈层（尤其校园 / Gen Z 密友）用低成本、强情绪的方式，把「没发出来的瞬间」变成可共享的故事，而不是又一个公开 feed？

Scoopic 的公开定位是：**Your AI Paparazzi** —— 个人「狗仔小狗」从相册与日常中挖 scoop，讲给真正的朋友听。

---

## 2. 产品定位

| 维度 | 定义 |
|------|------|
| 一句话 | 面向密友圈的 AI 叙事社交：把相册里的未发布瞬间变成可互动的「scoop」 |
| 核心隐喻 | AI Paparazzi Puppy（Scoopy）—— 好奇、八卦、好笑，而不是严肃相册整理 |
| 非目标 | 不做公开广场、不做泛关注者增长、不做传统图库云盘 |

**差异化：** 不是「又发一张图」，而是「AI 帮你指出图里不对劲 / 有故事的地方」，用 spot 放大镜 + 旁白把发现感做出来。

---

## 3. 目标用户

### 3.1 主用户（P0）
- 美国高校 / 高中年龄段学生（Scoopic 官宣与 UGC / Campus 项目均指向此）
- 有稳定小圈子（宿舍、Greek Life、社团、固定局）
- 习惯短视频与表情包式叙事，对「内部梗」敏感

### 3.2 次用户（P1）
- 同一圈层中的「相册贡献者」（常拍但不爱发）
- 内容创作者 / Campus Ambassador（增长侧角色，不完全是 C 端价值用户）

### 3.3 关键场景
- 派对 / pizza night 后回看
- 发现朋友相册里「没发的那张」
- 小组一起玩 Scoopy 揭秘

---

## 4. 目标与成功标准

### 4.1 产品目标（demo / MVP 阶段）
1. 让评审者 30 秒内理解「AI 狗仔挖密友 scoop」的核心循环
2. 用可点击 demo 验证：旁白 + spot 揭秘 + 情绪反馈（点赞心雨）是否够「好玩」
3. 为后续商业化路径讨论提供统一产品语言

### 4.2 体验成功标准（demo）
- [ ] 用户能理解「Found in Lisa’s photos」的来源叙事
- [ ] 至少完成 1 次 spot 揭秘并感到「有八卦感」
- [ ] Scoopy 被感知为角色，而不只是装饰 icon
- [ ] 愿意转发链接给 1 个朋友一起点（定性）

---

## 5. 核心用户旅程（MVP）

```
进入 App / Demo
  → 看到 Scoopy + 一条「12m ago」旁白
  → 主图上出现 spot（what's wrong? / who's that?）
  → 点 spot → 展开「THE SCOOP」揭秘图 + 文案
  → 点赞 / 反应 → 情绪反馈（心雨）
  → （完整产品）邀请密友进同一组 / 看到更多来自好友相册的 scoop
```

## 6. 功能需求

### 6.1 P0（当前 demo 已覆盖 / 应对齐）

| ID | 需求 | 描述 | 验收 |
|----|------|------|------|
| F1 | 手机框 Feed | 状态栏、标题、头像、主图卡片 | 视觉完整可滚动 |
| F2 | Scoopy 互动 | 点击小狗有反馈（弹跳 + 气泡） | 每次点击有明确反馈 |
| F3 | 旁白展开 | 点击 caption 展开 AI 叙述 | 展开/收起正确 |
| F4 | Spot 热区 | ≥1 个圆形放大镜热区 + 文案标签 | 可点、有标签 |
| F5 | Scoop 揭秘 | 展开替代图 + THE SCOOP 文案，可关闭 | 开合流畅 |
| F6 | 点赞心雨 | Like 触发粒子/心雨 | 视觉反馈明显 |
| F7 | 来源文案 | 「Found in X’s photos」 | 文案可见 |

### 6.2 P1（完整产品方向，demo 未做）

| ID | 需求 | 描述 |
|----|------|------|
| F8 | 密友小组 | 邀请 ≥5 人的 close group（与官方 Creator FAQ 一致） |
| F9 | 相册授权 | 本地/云相册扫描与权限管理 |
| F10 | Scoopy 个性化 | 每人一只 puppy，风格/语音差异 |
| F11 | Scoop 流 | 多条时间线 scoop，可刷、可回看 |
| F12 | 语音旁白 | 神经语音讲 scoop（官网已有音频资产形态） |
| F13 | 推荐邀请 | 组内 referral、验证学生身份 |
| F14 | 内容安全 | 敏感内容过滤、仅组内可见、可举报 |

### 6.3 明确不做（本期）
- 公开推荐算法广场
- 电商货架 / 直播带货
- 完整对标 Scoopic 的像素级复刻（demo 为原创资产）

---

## 7. 非功能需求

- 静态前端可离线/本地打开；首屏可交互 < 2s（本地）
- 移动优先；桌面以手机框为中心
- 隐私默认：demo 阶段无真实用户数据；正式产品需相册最小权限与组内可见

## 8. 商业化研究（公开信号 + 推断）

### 8.1 目前公开可见的「阶段」

Scoopic **尚未公开成熟的 C 端付费价目表**。当前公开动作更像 **增长与验证期**：

1. **App Store Pre-Order**  
   官网主 CTA 为 Pre-Order，链到 App Store（`id6781188057`），说明优先拿预购 / 安装意图，而不是先卖广告。

2. **重金买校园与 UGC 供给**  
   - UGC Creator：约 **$500/月底薪** + 单视频观看里程碑奖金 **最高约 $2,000**（官方 FAQ 称多条视频奖金不设条数上限）  
   - 邀请合格学生好友：FAQ 写明约 **$20 / 合格邀请**（需完成步骤并通过验证）  
   - Campus Ambassador：校园活动、Greek Life、派对场景地推 + 推荐奖励  
   这是典型的 **paid seeding**：先把「密友小组」密度打起来，再谈变现。

3. **商标覆盖面暗示远期能力**（USPTO 序列号 99815338，PIXELBEAT PTE. LTD.）  
   Nice 分类同时覆盖：
   - **Class 9 / 42**：社交软件、多媒体编辑、移动应用  
   - **Class 45**：在线社交 / **AI 社交**、介绍服务等  
   - **Class 35**：广告营销、社交网络广告、**消费者画像**、在线市场  
   → 法律层面预留了 **广告 / 营销 / 画像 / 市场**，不等于已经上线这些变现，但说明公司在商标上不为「纯订阅」单一路径锁死。

4. **公司形态**  
   LinkedIn 等公开信息：新加坡实体 PIXELBEAT、私立、约 11–50 人量级、2026 年成立语境；职位侧偏 Product Ops / AI+Social / UGC —— 增长与内容运营权重高。

### 8.2 最可能的商业化路径（按时间线推断）

| 阶段 | 策略 | 逻辑 | 风险 |
|------|------|------|------|
| **0. 获客期（当前）** | Pre-order + 付费 Creator/Campus + Referral | 密友产品必须「成组激活」；付 CAC 买小组密度 | 单位经济差；补贴停了就掉 |
| **1. 留存验证** | 免费核心 scoop 体验，强社交钩子 | 证明周活小组、回访、二次揭秘 | AI 成本与隐私反噬 |
| **2a. 订阅（高概率主路径）** | 「Scoopy Plus / Gold」：更多 scoop、语音、更长回忆、去限制、自定义 puppy | 对标 Locket 等密友社交：订阅可成主要收入 | 学生付费力弱，需低价年付 |
| **2b. 轻广告（中概率）** | 组外/轻量广告、品牌派对滤镜、校园品牌合作 | 商标 Class 35 已埋伏笔；品牌爱 Gen Z 校园场景 | 破坏「密友安全感」则流失 |
| **3. 品牌与校园 B 端** | 活动激活、赞助派对、品牌 UGC、Greek Life 打包 | 已有 Campus / Creator 基础设施可复用 | 需合规与披露 |
| **4. 远期可选** | 创作者分成、数字纪念品、限定 Scoopy 皮肤 | 角色 IP（小狗）适合周边与皮肤 | 需 IP 与用户资产沉淀 |

### 8.3 为什么「订阅 + 品牌」比「纯广告」更贴这个产品

- 产品承诺是 **小圈层私密惊喜**；信息流广告会直接打脸定位。  
- AI 挖相册有 **持续推理成本**，订阅更利于覆盖 COGS。  
- 小狗角色 + scoop 揭秘适合卖 **高级旁白 / 更多揭秘次数 / 主题皮肤**。  
- 校园大使网络天然可转成 **品牌校园营销渠道**（规模起来之后）。

### 8.4 单位经济粗框架（讨论用，非实测）

假设（需验证）：
- 成组激活：邀请 ≥5 人，组周活
- Creator CAC：底薪 $500 + 奖金 + $20/合格邀请 —— **早期 CAC 很高，靠密度而非单用户 ROI**
- 若后期 ARPU（订阅）约 $3–5/月（对标同类密友订阅量级），则必须：
  - 降低付费获客占比，转向病毒邀请
  - 提高小组留存与付费转化（解锁更多 scoop / 语音）

### 8.5 对「我们这版 demo / 需求」的启示

1. Demo 应继续强化 **揭秘快感与组内分享欲**（这是未来付费与病毒的前提），而不是堆广告位。  
2. 若做商业化原型，优先画：**免费揭秘次数耗尽 → Plus 订阅**，以及 **组邀请进度条**（对齐官方「至少 5 个朋友」）。  
3. 品牌合作适合放在 **派对主题 / 限定 Scoopy 皮肤**，不要插入 scoop 正文中间。

## 10. 开放问题

1. 正式产品是否坚持「仅密友小组」，还是允许弱关系围观？  
2. Scoop 由模型自动生成，还是人机共创（用户可改旁白）？  
3. 首发市场是否只做美国校园？  
4. 订阅权益清单的第一刀砍在哪：次数、语音、历史库，还是皮肤？
